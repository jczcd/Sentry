# Isaac Lab 战术任务骨架

这里定义与部署栈一致的边界，但不声称上传的旧 USD 已经是可训练机器人。旧资产缺少
可验证的真实质量、惯量、摩擦、轮组控制和传感器外参；在这些量没有标定前直接大规模
训练，只会得到利用仿真漏洞的策略。

## 固定契约

- 观测：161 维，与 `RMUC-OfflineRL/rm_rl/data/features.py` 同序。
- 动作：10 维，`goal_dx, goal_dy, weapons_free, target_prob[7]`。
- 战术频率：1 Hz。
- 底盘内环：100 Hz 或更高，由环境内部的确定性控制器执行。
- 训练内环：PyTorch/PhysX 内存，不经过 ROS 2。
- ROS 2：作业启停、单环境评估、回放和导出后的策略部署。

`contract.py` 可以在没有 Isaac Lab 的机器上验证批次形状、动作解码和奖励分项。
`sentinel_direct_env.py` 是按当前 `DirectRLEnv` API 写的资产适配模板；填入并验证
`robot_cfg` 后再注册为 `Sentinel-Tactical-Direct-v0`。

## 需要完成的资产适配

1. 从迁移后的 USD 确认 Articulation Root 和底盘刚体 prim。
2. 将四轮/麦轮驱动映射为底盘 X/Y 速度；禁止训练任务直接写电机力矩，除非目标就是
   底盘控制。
3. 把 6 个己方、6 个敌方、建筑、经济和裁判状态映射到 161 维槽位。
4. 加入碰撞、出界、热量、弹量和失联终止条件。
5. 在 1、16、256、1024 环境逐级验证显存和实时系数。
6. 加入质量、摩擦、时延、噪声、外参和丢包随机化。
7. 用同一输入样本逐元素对比 ROS 2 `observation_schema.py` 与训练环境，最大误差应
   小于 `1e-5`。

## 为什么不让每个物理步走 ROS 2

并行强化学习通常有数百至数千环境，每个环境的物理频率又远高于 1 Hz。把这些步通过
DDS 序列化会显著降低吞吐，也引入与训练无关的调度抖动。ROS 2 仍是系统“总调度”，
但不是 GPU 物理内存总线。
